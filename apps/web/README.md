# @repo/web

TanStack Start frontend for the todo demo: you add a todo, a Mastra workflow saves it
and an AI agent comments on it a moment later.

## The one architectural rule

The browser never talks to Mastra, the database, or the AI gateway. Every request goes:

```
browser  ->  /api/todos (this app's server route)  ->  MASTRA_API_URL/todos  ->  workflow
```

`src/lib/mastra.ts` is the only place that knows the upstream URL, and it is imported
solely from server route handlers. That keeps the upstream address (and any future
credentials) off the client and gives one place to normalise upstream failures — a
connection error to Mastra becomes `502 {"error":"Mastra server unreachable"}`.

The agent's comment is written asynchronously, so `POST /api/todos` returns `202
{"runId":...}` before the comment exists. `/todos` polls `GET /api/todos` every 2s
(TanStack Query `refetchInterval`) and shows a pulsing "agent is thinking…" placeholder
on todos with no comments yet. Making that gap visible is the point of the demo.

## Routes

| Path         | File                       | What it is                                        |
| ------------ | -------------------------- | ------------------------------------------------- |
| `/`          | `src/routes/index.tsx`     | New-todo form; POSTs to `/api/todos`, then navigates to `/todos` |
| `/todos`     | `src/routes/todos.tsx`     | Polling list of todos with agent comments          |
| `/api/todos` | `src/routes/api/todos.ts`  | Server route: `GET` + `POST`, validates and proxies to Mastra |

## Scripts

| Script      | Command                      | Notes                                              |
| ----------- | ---------------------------- | -------------------------------------------------- |
| `dev`       | `vite dev --port 3000`       | Loads `apps/web/.env`                              |
| `build`     | `vite build`                 | Vite + Nitro; emits `.output/`                      |
| `start`     | `node .output/server/index.mjs` | Production Node server; reads `PORT` (defaults to 3000) |
| `typecheck` | `tsc --noEmit`               |                                                     |

`start` is the Nitro `node-server` output entrypoint — `vite build` writes it and
records it in `.output/nitro.json` as `serverEntry`. Run `build` before `start`.

The preset is pinned to `node-server` in `vite.config.ts`. Left to auto-detect,
Nitro emits a *Bun*-targeted server whenever the build itself runs under Bun (as
it does inside the `oven/bun` Docker build image), and that artifact dies under
Node with `ReferenceError: Bun is not defined`. Pinning it keeps the output the
same everywhere.

`src/routeTree.gen.ts` is generated by the TanStack Start Vite plugin on `dev`/`build`
and is committed so `typecheck` works on a fresh clone.

## Environment

| Variable         | Default                  | Used by                                   |
| ---------------- | ------------------------ | ----------------------------------------- |
| `MASTRA_API_URL` | `http://localhost:4111`  | `src/lib/mastra.ts`, server-side only     |
| `PORT`           | `3000`                   | the production server (`bun run start`)   |

Local values live in `apps/web/.env` (gitignored); see the repo root `.env.example`.

`.env` is loaded in **dev only** — Nitro reads it when the dev server boots, and
deliberately does not in the built output, where the environment comes from the
platform. Running the production build locally therefore means passing the values
on the command line:

```sh
PORT=3000 MASTRA_API_URL=http://localhost:4111 node .output/server/index.mjs
```

Otherwise `MASTRA_API_URL` falls back to `http://localhost:4111` and, if nothing
is listening there, every request answers `502 {"error":"Mastra server unreachable"}`.

## Deployment

`Dockerfile` (built from the repository root) installs the workspace, runs
`bun run build`, and starts `node .output/server/index.mjs` on `PORT`. That is
what Rock8Cloud builds; see the root README for the full deployment steps.
